# 文本与多模态测试指标

依据[原始导出](../evaluation.json)，批次 `f263333e0db0e16e53b73a5a`，场景版本 `6feb4fe4b201b8a7`，验收口径 `end-to-end-v1`，分组版本 `task-modality-v1`。请求输出上限为16384 tokens，各适配器的实际上限以原始记录为准。

只统计261条 `arm=routed` 记录（87项×3种方案，含未测占位）；导出的531条记录还包含低价/高能力对照，它们不重复计入分母。本报告复用原判定，没有新增模型调用。

## 如何分类

- **GPU原始类型匹配**：比较 `assessed_profile.workflow` 与冻结用例的 `allowed_workflows`，只检查任务类型这一项。87项效果集没有其余六项属性的完整参考标签，不能计算七项全字段准确率。
- **后端调整后类型匹配**：比较 `profile.workflow` 与同一参考；这就是现有前端的 `workflow_fit`。后端会依据实际附件、明确输出类型等调整流程，不能把它全部归功于GPU。
- **输出完成**：目标返回 `complete=true`，不要求质量通过。无候选和正确拦截没有目标输出，因此不会计入完成数。
- **已评分答案通过（辅助）**：有效评审优先于原始自动评分，只统计已有pass/fail评分的子集。各模型分母不同，不替代整体验收排名。缺少类型记录和没有评分的样本只从对应诊断分母排除，仍在主指标分母。

例如：Decider的图表任务原始为speech，后端调整为vision；Decider和H2O的ASR原始为speech，后端调整为audio_understanding。调整后三者的多模态类型匹配均为11/11，但最终仅3项答案通过。类型正确不等于媒体内容正确或目标能力可用。

## 文本指标怎么验收

| 能力 | 当前验收依据 | 当前边界 |
|---|---|---|
| 对话、摘要、翻译、创作、专业问答 | 冻结任务要求、事实与格式约束；保存具体评审理由 | 开放题含助手辅助评审，不是独立人工金标 |
| 数学、抽取、JSON与资料问答 | 精确值、等价数值/分数、结构、给定证据和禁止的额外输出 | 只证明对应样本满足规则，不是领域总体准确率 |
| 代码与SQL | 按任务要求检查功能与格式；已有Python隔离功能测试，开放设计/审查逐项评审 | 生成SQL不等于连接数据库执行；围栏会导致要求原始代码的样本无法直接运行 |
| 文本向量与重排 | 重排核对目标文档位置；向量需另验检索效果 | 两个向量接口输出待评；检索质量用例未测，不能用返回维度当质量通过 |
| 多轮、工具、长上下文 | 需真实上下文、工具调用、长输入及对应验收 | 当前7项文本未测：4项工具/结构化接口、2项多轮/长上下文、1项检索质量 |

文本未通过分别为14、3、4项。Decider包含13项通用路由/输出模态问题和1项代码安全问题；Liquid包含2项路由问题和1项代码安全问题；H2O另有1项代码格式问题。这些是路由、执行与答案共同形成的端到端结果。

## 多模态指标怎么验收

| 能力 | 本批已得到的结果（三种路由方案） | 进一步评测指标 |
|---|---|---|
| 图像理解 | 2/4通过：蓝图、OCR；红图识别错误，图表答案内容正确但额外解释违反格式 | 扩展视觉问答内容正确率；OCR字符错误率CER；内容和格式分别记分 |
| 音频识别 | 0/1通过：词语正确，但输出多了时间戳，不满足“只转写说话内容” | 词错误率WER/字符错误率CER衡量内容；另记额外输出/时间戳的格式合规率 |
| 语音生成 | 英语1项待听评；中文1项未通过且有边界标记问题 | 文本读对比例、可懂度、自然度MOS及端到端延迟；当前没有MOS分数 |
| 视频理解 | 主体与动作1项通过；长视频时序定位1项未测 | 内容正确率；有时间段标注后计算时序IoU和定位召回率 |
| 图像生成与编辑 | 去背景损坏主体，1项未通过；文生图1项无可用执行型号且有边界标记问题 | 背景移除、主体保留和指令符合度分别验收；当前没有统一感知分数 |
| 视频生成 | 1项无可用执行型号且有边界标记问题 | 内容符合、跨帧一致、运动质量和生成时延，均需实际生成后验收 |
| 多图、音画同步、实时语音、说话人分离 | 4项未测；加上长视频时序定位，共5项多模态未测 | 差异识别、音画同步偏差、打断响应、说话人分离错误率DER，需对应输入与标注 |

WER/CER =（替换 + 删除 + 插入错误数）/ 参考词数或字符数，越低越好，可能超过100%；MOS为定义量表上的听评均分；时序IoU为预测与参考时间段的交并比，越高越好；DER衡量说话人时间归属错误。以上细粒度指标尚未在本批计算，不能把它们写成已有实测分数。

多模态16项的状态为：3通过、7未通过、1待评、5未测。7项未通过中，2项内容错误（红图、去背景）、2项格式违规（图表、ASR）、3项能力未交付且有边界标记问题（中文语音、文生图、文生视频）。这3项仍沿用原 `end-to-end-v1` 的失败判定；本次没有重评或调整分数。

三种方案引用了部分相同目标观察，不能把相同的媒体输出当作三次独立实验。GPU只读取文字和附件类型，真实媒体由Bedrock目标模型处理；这些通过率不代表GPU自身的识图或听音能力。

## 复核与使用限制

这是可见开发回归集的一次顺序执行；不能据此推断未来业务成功概率、并发吞吐或全部多模态能力。通过率是使用对应GPU分类器的完整路由方案结果，包含后端调整、候选过滤、目标模型和适配器的影响。已知边界标记问题及共享观察限制见[失败原因分析](../failure-analysis.zh.md)。

延迟与费用需要独立阅读：GPU服务往返、完整路由和目标执行的P50/P95分别统计；目标Token × 已知参考价只代表已知费用，不含常驻GPU、ECS、网络等基础设施。未知价格不能当零，也不能据此宣称完整的每成功任务成本已测得。

[机器可读指标与逐场景分组](metrics.json)保存源文件SHA-256、记录ID、原始/调整后类型和观察ID，可与[完整评测方法](../../../../docs/effectiveness-evaluation.zh.md)对照。生成器核验本批源文件SHA-256，并检查分类覆盖、重复记录和分组加总；其他批次需重新分析并发布分组报告。

在仓库根目录重建：

```bash
python scripts/report_gateway_modalities.py \
  --evaluation validation/independent_gateway/overall-metrics-2026-11-25/evaluation.json \
  --output-dir validation/independent_gateway/overall-metrics-2026-11-25/modality-breakdown
```
