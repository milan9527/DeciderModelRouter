# 匿名评测依据与 Liquid 选模微调 · 2026-11-26

当前部署策略为 `gpu-evidence-anonymous-table-v6`，默认 Liquid d1-2B，仍然两次 GPU：先判断七项需求，再从全部符合运行约束的配置选择模型。文本质量只使用 LiveBench；多模态保留专项依据。能力优先、均衡、成本优先均作为模型输入，不增加 CPU 质量淘汰、Top-K 或质量重选。

## 修复内容与证据

原 Liquid 对复杂证据的权衡不稳定。[25次原始诊断](diagnostics/original-choice/README.zh.md)显示：产线原输入选 Devstral，仅交换名称或选项顺序就改变选择；不是没有传入 LiveBench，也未发现上下文截断。名称、顺序敏感性不能解释为模型的可观测内部推理。

第二阶段现在使用匿名 `m000` 编号，候选证据放进共享表；显示名称、厂商及来源型号不进入候选卡。保留原分项、批次、测试与执行档位、费用、实际延迟、输出预算和约束。辅助均值只取同一主要批次的完整相关分项，不混合 LiveBench 1/2，不补未知值，也不据此在 CPU 上选赢家。实际模型 ID 在服务器映射，前端保留原始来源链接和记录。

仅调整输入还不够：7个已见上下文×3种偏好×正反两种排列，旧格式同配置一致6/21，新匿名格式7/21。增加固定的公开评测选模 LoRA 后，同一 eager 条件下，同型号一致从8/21到12/21，同配置从8/21到10/21；**顺序敏感性仍未消除**。能力优先14次测试中，选中本次主要批次最高辅助均值从3/14到8/14；微调后距离最高值的平均差0.813分。它不是业务正确率，也不是全部场景最佳模型证明。

选择概率与第一、二名差距现在保存在数据库，并展示在工作台、历史详情和 Agent 步骤。缺失或无效概率标记未知，不修改选择、不追加调用；该概率不是目标模型答题正确率。

## 训练方法与范围

基座 `LiquidAI/d1-2B@cfe5760ff5d5998f91d9ac56bd4b2dbd96996d41` 冻结，rank8、scale2，实际插入11个文本注意力 `o_proj` 模块，A/B为float32，输出增量转换到BF16。种子64119，AdamW学习率0.0002，160条训练、32条开发验证，2轮共320步，约466秒。按开发交叉熵选择第240步；开发目标首选一致26/32，不能作为业务成功率。

7个已见路由上下文采样12/24/36/48项候选，随机匿名重编号、打乱表及选项顺序；公开质量数值不变，价格为合成反事实价格。软标签是 `softmax((主要批次相关均值 - w*log2(1+合成费用/费用中位数))/1.5)`，能力/均衡/成本偏好的w为0/8/20，强模型收益为高时费用权重减半；缺主要分项的候选没有目标概率，但运行时仍可被选择。**这是自定义离线训练启发式，不是 LiveBench 官方公式或 OpenRouter 私有路由实现。** 业务回答、人工答题评分不进入训练。

适配器只作用于第二阶段、存在LiveBench主要批次的文本选模；第一阶段和多模态仍使用原权重。实际安装权重 SHA-256：`d9eeae6c4cda5d29b91f3f355d658377714cf5e6080ff6b83fae4d8dabfa048e`。[权重、许可和复现说明](training/README.zh.md)。H2O、Decider采用同一匿名证据格式，没有训练这份适配器。

## 概率、价格与编译检查

[完整统计](report.json)及[原始对照](diagnostics/)分别保留候选换序、价格交换和编译输出。2个质量接近的候选、2种反事实价格分配、3种偏好、正反顺序共12例/模型，预定义偏好行为符合9/12→12/12。价格为0.0001与0.02美元的合成值，**不能据此宣称实际节省费用**。

同一42个选模输入，eager与编译实际选择41/42一致；12个需求判断12/12一致。一条Agent均衡请求从Astra6.2变成Sol6.1，eager中前两者并列，编译出现概率差异；最大单项概率差约0.0364。保留这项未通过，不宣称数值等价。最终72项全部重新在编译生产路径执行，并非沿用eager答案。

最终路由P50/P95为763/805ms，两次GPU决策合计758/797ms，目标生成1294/18882ms。这是本地后端经SSM转发的私有HTTP，不含评测排队，不是CloudFront端到端。基线与训练重叠、初测与其他探针重叠，跨组耗时不用于因果加速结论。

最终74次路由全部两次GPU，共148次HTTP调用；68个独立任务第一阶段输入及答案与基线68/68相同。实际缓存读取81 tokens。74份输出只有6份具备可用参考价，已知部分合计$0.2108906；不等于总费用，不据此保证成本最优。

## 重算与重新测试

在仓库根目录执行 `python validation/independent_gateway/anonymous-evidence-2026-11-26/report.py` 可从已保存原始结果重算报告，不调用AWS。报告中的`optimized`键对应目录`adapter-initial`；最终记录的`arm=optimized`是现有工具的通用实验标记，以目录、suite版本和GPU元数据区分两次运行。

重新生成业务答案可运行现有 `scripts.run_latency_quality`，指定新的输出目录、此处`suite-final.json`、`--arm optimized`与已安装固定适配器的GPU地址；本地SSM转发到原生Liquid服务时使用`--gpu-path /v1/systemone`。这会产生实际Bedrock调用费用，需环境提供AWS权限和评测媒体访问。随后使用 `scripts.check_latency_code` 做隔离代码功能检查、人工核对开放题并保存与答案哈希绑定的reviews，再用 `scripts.summarize_latency_quality` 汇总。已见题目始终标为回归，不重新命名为盲测。

浏览器初次检查因断言在候选表查找本应位于选模卡的总概率而失败；修正检查定位后通过，未为此改动产品。正式API与浏览器都保留各自独立运行ID，浏览器的两次仅选模请求不计入11次API诊断分母。
