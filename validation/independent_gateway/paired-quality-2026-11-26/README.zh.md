# 三种路由方案的同题质量对照

本轮专门检验“两次GPU分段调用是否值得采用”。默认决策模型均为 Liquid d1-2B；路由在现有 A10G GPU 服务上实测，目标回答由新发起的 Bedrock 请求生成。正式服务仍使用一次联合决策，本实验没有部署，也没有把测试会话写入线上历史。

本轮已完成三组各159项的同题对照。**两次GPU方案值得继续优化，但本轮不足以支持直接替换生产默认。**它缩短了路由提示、提高了若干代码与业务题的正确性，仍存在计算错误、虚构业务动作、格式违约和目标调用失败。这是一轮诊断性观测，不是重复试验所得的稳定胜率。

42项软件测试通过，Ruff检查通过；11份冻结源码未改变，三组候选证据快照一致，85份独立评审记录均完成。参见[运行验证](verification.json)、[线上服务未变更](production-unchanged.json)和[发布扫描](publication-scan.json)。

## 建议

继续以两次GPU方案作为实验候选。优先修复结构化输出能力筛选导致的空候选、已不可调用的Legacy端点、原生工具消息不兼容，以及多轮降档时丢失计算和事实要求的问题；增加业务数值与未核实动作的验证。再用新的未见行业题和重复试验验证质量、延迟与费用。本轮结果没有回灌到路由证据、没有切换线上默认，也没有发布到前端历史。

## 对照方式

| 方案 | 一次请求中的决策过程 | 实现 |
| --- | --- | --- |
| 联合一步 `joint` | GPU同时回答7项需求问题和1项选模问题；服务器检查选择是否相容 | 当前生产 `assess_and_select` 函数 |
| 两次GPU `two_stage` | GPU评估7项需求 → 按硬约束筛选 → GPU读取实际评估结果与全部合格候选，选择模型 | 本轮实验脚本 |
| GPU＋CPU `cpu_policy` | GPU评估7项需求 → CPU按质量门槛、质量区间、价格与会话策略选择模型 | 上轮未部署的策略实验 |

两次GPU方案没有按固定 Top-K 淘汰候选。第一阶段结果真实写入第二阶段提示；第二阶段只有选模一项问题。空候选集不强行选择，也不调用第二次GPU。这里是本项目的可复现实验，不代表复刻了 OpenRouter 未公开的内部实现。

## 范围与公平性

每组计划159项：原87场景、8项已有复杂诊断、12行业×4轮、16项本轮新增诊断。三组合计477个评分项，不能把这个数量当作目标API调用次数：工具循环和检索用例会产生多次调用，明确的能力缺口不会调用目标。

新增诊断覆盖事故级免赔与发票去重、库存优先级、储能净收益、加权缺陷率、紧急排程、暂停区间并集、验收/发票双条件、未核实业务动作、严格告警阈值、历史更正、历史未知字段、多图顺序及4个可执行函数。题目在本轮执行前冻结，没有用本轮回答调路由。它们依据已发现的弱点设计，仍是可见的诊断集，不是独立隐藏基准。

- 三组重新运行目标调用，不复制旧答案或旧分数。模型目录、评测证据与输入版本保存在清单和快照中。
- 输出请求上限统一为16,384 tokens，实际还受端点上限约束；没有为某组临时增加额度，没有目标重试或模型回退。
- 同题轮换三组的提交顺序，最多两个活动用例/行业会话。GPU路由串行进入实验锁，避免三组相互争抢GPU；实验等待时间单独记录。
- 行业会话各自保留成功的原生消息和工具结果，不跨组共享答案。后续轮次可能承接各组不同的历史，这是会话策略实际效果的一部分。
- 使用现有本地原生 Bedrock Agent 适配器及合成只读业务工具；**不是部署在 AgentCore Runtime V2 内的端到端测试**。
- 三组均启用原生提示缓存。相同模型/前缀可能共用服务商缓存，没有隔离服务商缓存状态；耗时不能解释为严格的冷缓存基准。

## 评分与证据

主通过率为“已验证通过项 / 全部159项”；失败、待复核和未测都保留在分母。原143项与新增16项单列；另外拆分文本/代码/检索、多模态和行业四个阶段。预设边界的正确拦截单列，不当作生成了合格答案。

明确数值、JSON、顺序和检索排序按固定答案检查。开放回答由独立 Bedrock 评审模型 Claude Sonnet 4.6 按同一任务标准评审：隐藏方案名和所选目标模型，稳定打乱答案顺序，每份回答分别判定，不强迫选赢家。评审模型自身也可能被某个路由选为目标，因此这不是完全独立的人工评审。保存原始评审和助手逐条复核的修正理由。

基础3个函数与新增4个函数在无网络、无凭据、只读、非root并限制资源的容器中执行。检查全部返回版本、边界、异常类型和输入不变；函数功能与“只返回裸代码”的格式要求分别记录。4个正确控制实现和1个故意错误实现验证检查器能接受正确结果、拒绝错误逻辑。行业代码按源代码静态复核，不能描述为完整执行验收。

SaaS代码额外验证了一处具体SQL疑点：隔离PostgreSQL 15中，`jsonb_build_object`的未指定类型参数报错，显式`::text`控制通过，并与psycopg 3官方参数绑定说明核对。保存最小复现、控制和来源；这不是整套行业代码或数据库并发测试，临时容器已删除。

音频和图片编辑检查实际产物。本轮增加支持中文的 AWS Transcribe 内容检查，先以 Polly 生成的“正确句子、不同句子、英文句子”作3个已知控制；控制均精确转写后再核对目标WAV。两份中文音频未通过该自动检查，另一组语音生成超时。这里没有人工听审，不评价音色、自然度或完整发音质量。

联合一步的英文音频最初被 Voxtral 转写为西班牙语；追加经4个英文/西班牙语控制校准的 Transcribe 交叉检查，实际英文内容匹配，已修正为通过。原始误判和交叉证据都保留。检查使用的S3临时对象、版本及Transcribe任务均清理；没有写入产品会话历史。

实时搜索、真实业务数据库/外发操作、长文档与部分复杂媒体、压力和故障注入的缺口明确保留。仅拒绝保证收益或伤害请求的回答，其拒绝边界正确；若缺少冻结验收标准要求的风险说明或安全求助建议，完整验收仍未通过，不能把这类失败解释为提供了有害内容。

首批三个评审响应将嵌套数组错误序列化为字符串。保留失败原文，改用平铺标量工具字段重新评审；评分指令不变，没有重新生成目标答案。

复核还发现[政务产能题的字段歧义](fixture-ambiguities.json)：`cases_per_day=4`没有定义每人还是团队口径，隐藏参考答案却按每人4件计算。受该口径直接影响、没有其他独立错误的结论保留为待复核；自身算术矛盾、未查询所需数据或代码错误仍判未通过。没有在执行中改题，也没有用参考答案里未向目标提供的信息否定合理假设；下一轮应明确字段单位后重新测试。

## 复现

运行需要可访问现有GPU服务以及本项目所需的 Bedrock/Secrets Manager 权限，调用会产生费用。GPU地址通过本地SSM转发提供，密钥仅从Secrets Manager读取。本轮使用Python 3.12.15、speech SDK 0.13.1和Pillow 12.3；语音扩展需要Python 3.12。代码检查还需要Docker，音频交叉检查需要Polly、Transcribe及隔离S3前缀的权限。

```bash
python -m scripts.run_paired_quality --output .deployment/paired-quality-20261126 --group all
python -m scripts.review_paired_quality --input .deployment/paired-quality-20261126
python -m scripts.check_paired_code \
  --input .deployment/paired-quality-20261126 \
  --image decider-model-router:single-pass-20261126
python -m scripts.review_profile_media \
  --input .deployment/paired-quality-20261126/joint --cases tts image-edit
python -m scripts.review_paired_chinese_audio \
  --input .deployment/paired-quality-20261126 --bucket YOUR_PRIVATE_PROJECT_MEDIA_BUCKET
python -m scripts.review_paired_chinese_audio \
  --input .deployment/paired-quality-20261126 --bucket YOUR_PRIVATE_PROJECT_MEDIA_BUCKET \
  --arms joint --target-case tts --output-name english-audio-cross-check
python -m scripts.summarize_paired_quality \
  --input .deployment/paired-quality-20261126 \
  --output .deployment/paired-quality-20261126/summary.json
```

完成记录不会自动重跑。媒体检查对各方案分别运行；上述命令中的joint仅是一个例子。独立评分之后仍需源答案复核，最终修正保存在`assistant-audits.json`，不能把新一轮自动评分当作复现了本轮助手的逐条判断。原始请求/回答、路由提示、GPU计算次数、候选证据、代码检查、媒体产物、评审及修正均用于审计；私有会话数据库和凭据不发布。

路由耗时从进入实验GPU锁后开始，包括本地策略处理与经SSM转发的GPU HTTP往返；不包含等待实验名额的时间。GPU服务端耗时和实际前向次数另存。目标耗时仅对取得输出的观测统计，超时/错误另列，不能将该分位数作为所有请求的端到端SLA。费用是已知价格项目的参考值，未知价格、检索分组和未取得用量的失败不能按零计费，也不等于AWS账单。
