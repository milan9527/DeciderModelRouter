2026-11-26，策略 `gpu-evidence-livebench-preference-v5`、偏好元数据 `livebench-preference-v3`。

文本选模只使用LiveBench相关分项；不再把旧6题通过数、格式通过数、开发回归评分或OpenRouter文本基线传给GPU。“能力优先 / 均衡 / 成本优先”继续作为任务选项，均由GPU权衡，默认仍为均衡。

本次取消上一版针对能力优先的程序质量处理：没有“高5分淘汰”、质量PASS/REJECT标签、缺少LiveBench或旧答题实测即不合格的规则，也没有额外质量重选。正常仍为第一次GPU判断七项需求，第二次GPU选择目标。程序保留接口能力、权限、配额、上下文、明确模型限制、预算及显式延迟约束。

## 输入与行为验证

[639项软件测试](software-tests.json)全部通过，无失败或跳过。软件检查中外部服务多为模拟，不代表模型答题准确率。

- 将所有旧答题的通过数、样本数、待评分数替换为不同数值，推理/代码/通用/客服四类×三种偏好的候选、偏好元数据和GPU输入保持完全一致。
- 改变LiveBench Coding成绩会改变传给GPU的分项；候选资格不按该分数预先淘汰。
- 能力优先下，模拟GPU选择低分或缺少LiveBench的候选时仍只调用一次选模GPU；返回不在选项中的编号则不执行目标，不增加质量重选。
- 旧推理档答题测试的有无不再改变资格；明确设置最大延迟时，仍检查精确配置的运行测量。
- LiveBench均分不转换成业务成功率；显式要求最小业务成功率时报告无法核验。
- 多模态仍提供专项依据；Agent工具协议、角色消息、历史、缓存、执行故障回退及旧票据版本检查由既有回归覆盖。

## 结果解释

缺少LiveBench分数的型号仍可被GPU选中。取消额外质量门槛后，偏好由模型执行，不能承诺“能力优先”必选榜单第一名，也不能承诺最优业务答案。公开测试档位与实际Bedrock配置可能不同，分数不视作默认档能力保证。

本次上线诊断与历史56项质量回归分开记录。上一版40/56完整验收、48/56内容正确仍保留在历史报告和页面，不作为当前策略的准确率。没有重新运行全面质量评测。
