### 决策模型延迟

性能只统计Liquid d1-2B的需求判断和选模两个阶段，不计完整网关路由、目标生成或公网请求全程。以下106次决策共212次前向计算，包含Agent内部调用和产线超时前已完成的决策。

| 决策阶段 | 样本数 | 服务内P50 / P95 | 阶段调用P50 / P95 |
|---|---:|---:|---:|
| 第一阶段：需求判断 | 106 | 102 / 181ms | 109 / 685ms |
| 第二阶段：模型选择 | 106 | 542 / 623ms | 596 / 725ms |
| **两阶段合计** | **106** | **687 / 732ms** | **733 / 1381ms** |

服务内计时来自 `decision_calls[].timings.service_reported_ms`，覆盖Liquid输入处理、前向计算、CUDA同步及清理，不含锁等待和HTTP。阶段调用计时来自历史中的 `assessment_ms`、`selection_ms`、`model_decision_ms`，包括决策调用排队、通信、校验和选模输入准备。两者均不是纯GPU内核时间。

P50/P95采用最近秩法，合计按每次决策的两阶段总和计算，不直接相加各阶段分位数。数值四舍五入到毫秒；普通任务并发上限2，不能据此推导高并发容量。[汇总、逐次计时及原始文件哈希](decision-latency-2026-11-27.json)单独保存，未重新调用模型或改写原评测文件。
