## 线上机制与优化

1. 第一次 GPU 同时判断七项需求：任务用途、难度、使用更强模型的收益、时延偏好、工具、结构化输出和语言。
2. 后端按实际能力、接口适配、预算、配额和精确端点可用性筛选候选。
3. 第二次 GPU 读取第一阶段判断、当前任务和历史上下文，以及全部合格配置的评测、样本量、输出完整性、价格和延迟证据，选择目标配置。没有固定行业模型名单或程序 Top-K 淘汰。
4. 目标模型执行；会话粘性是选择时的依据，仍允许每轮切换。明确调用失败且尚未输出时，保留需求判断，由 GPU 在剩余候选中重新选择。

本次同时修复：

- **上下文遗漏**：选模保留首轮要求、最近对话的开头和结尾、最新工具结果；不再把第二阶段历史压成每条200字符。路由仍有长度裁剪，不保证任意长历史完整进入决策模型。
- **JSON误判**：普通“只输出JSON”不再直接等同于接口强制 JSON Schema。真正要求约束解码时仍检查执行能力。
- **原生工具兼容**：忽略提供商返回的空白文本块，同时继续校验工具名称、参数及调用配对。捕获的 Nemotron 合法 `tool_use` 响应经修复后适配成功，见[回放验证](protocol-fix-verification.json)。
- **端点可用性**：重新实测 DeepSeek R1，当前账户的精确端点仍被提供商拒绝，已排除；Marengo 2.7 实际可调用，保留。没有整体禁用 Legacy 型号，见[实测记录](availability.json)。
- **媒体适配边界**：存在质量评测不代表已实现媒体执行接口，不能据此绕过适配器检查。
- **可观测性**：前端分别展示两阶段耗时、请求次数和实际前向次数；历史与性能页把两阶段、历史联合决策及更早的单独选模分开统计。未知前向次数显示未知。

只读工具与业务动作边界也加入行业系统说明，但后面的真实结果表明，提示词尚不能消除计算错误或虚构已执行动作。

## 结果的使用范围

本次确认两阶段机制、前端、历史存储和原生 Agent 调用已经上线。行业测试仍暴露金额/单位错误、损耗公式错误，以及将建议写成已执行动作；切换到更贵模型也不保证正确。独立评分模型本身也存在漏判，最终报告不能直接照抄其 `pass` 字段。

本轮没有全量重评所有目标型号，也没有证明缓存收益、成本下降或全面质量提升。此前直接端点评测和本次可用性修正继续参与决策；本页的行业复核尚未自动写回选模分数。后续重点是让业务阶段、计算依赖与只读边界更稳定地进入选模依据，并用确定性核算检查防止错误沿多轮历史传播。
