# 评测指标说明与输出预算调整

本次根据用户反馈，将界面和报告中的“工作流相容”改为 **“任务类型判断正确 / 已检查”**，说明为“识别的用途与请求匹配，例如没有把文字问候误分成语音生成”。该指标不代表全部分类属性都正确，也不代表所选型号最优。

将原“质量通过 / 已评分”明确为 **“任务通过 / 已判定”**。通过要求完整输出并满足验收规则，同时新增两个分开的计数：

- **完整答案不合格**：输出已完成，但内容或格式不满足验收规则。
- **输出未完成**：模型未完成最终输出，包括 token 截断。它表示本次任务尚未交付，不能当作模型答错。

调用错误、待评和能力缺口仍分别记录。逐场景和对照策略中的截断结果显示“输出未完成”，原始自动评分、评审和历史预算保留。

## 原批次的失败拆分

以下来自原 2048-token 主批次，只更新指标说明与分类展示，没有新推理或重新判分。

| 决策模型 | 任务通过 / 已判定 | 完整答案不合格 | 输出未完成 | 调用错误 |
|---|---:|---:|---:|---:|
| Decider | 40/50 | 7 | 3 | 0 |
| Liquid | 50/60 | 6 | 4 | 0 |
| H2O | 49/60 | 7 | 4 | 0 |

“已判定”包括通过、完整答案不合格、输出未完成和调用错误；待评与缺口另列。[原批次完整结果](../full-effects-2026-11-25/report.md)。

## 新评测预算

界面和 API 默认从 1024 提高到 **16384 tokens**；命令行默认从 2048 提高到 **16384**。仍可选择较小上限；自定义用例未设置上限时使用本批上限，显式设置更低值时保留。推理与最终回答共用预算，模型可以提前结束，较大上限可能增加时间和费用。

每个历史结果都显示该批输出上限，避免把旧批次当作 16384 的成绩。API 字段保持兼容，增加 `answer_failed` 和 `output_incomplete`。

## 16384-token 真实补测

在正式域名上仅新增 **1 次 H2O 分类、1 次 Bedrock 调用**，重试之前 8192 上限仍截断的并发幂等问题。为复现原低价对照，使用相同题目、低价策略，验证目标仍为 GPT-6 Luna。API 请求和自定义任务均未填写输出上限，实际采用新默认 16384。

| 条件 | 8192 上限的旧观察 | 16384 上限的新观察 |
|---|---:|---:|
| 输出结果 | 耗尽预算，无最终答案 | 完整，结束原因 end_turn |
| 实际输出 token（含推理） | 8192 | 13602 |
| 目标调用耗时 | 64.70 秒 | 107.67 秒 |
| 已知参考费用 USD | 0.0040998 | 0.0068048 |

新答案说明了业务幂等键、持久唯一约束、流水与原子余额增量同事务、并发竞争及提交前后崩溃恢复，助手依据原题验收标准评审通过。没有执行数据库故障注入，也不是独立人工金标。参考费用不是 AWS 账单。

两次目标调用的文本哈希、模型执行标识、配置标识、任务分类及推理参数一致。未固定生成随机种子，也没有重复采样，因此只说明这个补测观察在较大上限下完成，不据此修改全场景分数。[原始输出和评审](budget-16384/evaluation.json) · [控制条件与用量对比](budget-16384/comparison.json) · [实际请求](budget-16384/request.json)。
