本批后台执行约 **34 分 37 秒**，包含顺序模型调用和记录保存。目标分位数只使用有返回耗时的路由观察；无法取回的错误耗时不补零。顺序延迟不能推导并发吞吐。

166 个独立目标观察中，145 个有完整用量与参考价格，已知部分共 **$3.0863004**；前轮为 146/166、**$2.201986**。两者都包含对照调用，都是参考费用小计，不是 AWS 账单；未知媒体价格、未取回用量及 GPU/ECS/存储/网络费用未计入。覆盖不同，不能把小计比例解释成完整费用涨幅。三种路由方案含共享观察，其费用不能直接相加。

主要预算发现：

- 并发设计的三种路由结果均完整通过。一份低价 Luna 对照使用 **10791 输出 token、85.25 秒、参考 $0.0053993**，覆盖稳定幂等键、同事务入账、提交边界恢复及重试。
- **更大上限不能保证完成。** 安全审查低价对照的 Haiku 5.5 仍耗尽 16384 token，仅返回推理，没有最终答复，耗时 67.10 秒；高能力 Opus 5.5 对照返回 HTTP 502“当前适配器不支持的结果”。两者各是一个独立观察，被三组引用；未自动重试。后者未保存可用于进一步判断的原始停止原因/用量，不能擅自归因于限流或内容拒绝。
- 本轮 H2O 微型故事用了 1861 token 就完成，而前轮在 2048 截断。单次生成会变化，不能把所有改善都归因于预算增加。两轮没有固定生成随机种子或重复采样。
- 16384 是批次请求上限。**Sonic 语音适配器仍上限 1024**，实际值保存在输出的 `effective_max_output_tokens`；图片编辑和向量任务不使用普通文本输出预算。

上述对照异常保存在 [exception-observations.json](exception-observations.json)，与路由方案的零调用错误分别呈现。

## 质量问题与可改进项

1. **分类边界未改善。** 三种决策模型的任务类型正确计数与前轮一致。Decider 仍会给文字 `hi` 生成语音；普通 JSON 与提供商强制 Schema 的混淆仍导致部分无候选。增加目标输出预算不会改变前置分类。
2. **代码格式与安全修复仍有缺陷。** 9 份独立函数输出在无网络、只读、非 root、限资源容器中执行，8 份通过。失败函数包含题目禁止的 Markdown 围栏，原样执行语法错误，不代表已证明算法错误。安全审查路由答案虽使用 `shell=False`，但主机名正则允许 `-f` 等选项，仍留下选项注入问题。[代码结果](code-results.json)保存测试数、源码哈希、镜像和失败详情。
3. **图片及转写需区分内容和格式。** 红图仍被回答为 “Blue.”；蓝图同样回答 “Blue.”，内容正确，沿用前轮标准追加通过评审并保留自动精确匹配失败。OCR 为 2048，正确。图表识别 B 正确，但多了题目禁止的解释；ASR 本轮词语内容正确，但附加时间戳，违反“仅转写说话内容”，仍不通过。
4. **视频改善、图片编辑未改善。** 本轮视频准确描述红色花苞绽放，与[相同参考分镜](../full-effects-2026-11-25/video-contact-sheet.png)一致。[本次去背景对照](media/image-edit-0465-comparison.png)仍将蓝柱删除、红柱大幅透明，编辑质量失败。语音只核对 WAV 结构和 2.72 秒时长，没有听音，不冒充语音质量通过。[媒体证据](media/inspection.json)。
5. **质量门槛之上仍有选模费用空间。** 在双方通过且价格可比的已测场景中，Decider、Liquid、H2O 分别有 **6/32、7/50、21/49** 项存在更便宜的已测通过方案；这只相对于本次低价/高能力对照，不是全模型最优解。Liquid 在本集上质量与路由延迟较好，仍需独立样本复核。

后续优化应优先联合选择推理强度与输出上限、修正任务/模态和 JSON 边界、补充媒体质量证据，再在达到质量要求的候选中控制费用。本轮保持生产分类、选模和目标配置不变，没有按可见题库训练路由器。
