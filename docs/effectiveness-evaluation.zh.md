# 路由效果评测

评测入口：[独立网关 → 路由效果评测](https://d3eipg2g3l3an3.cloudfront.net/#evaluations)。

现有七项分类评测仍保留，用于定位分类差异。新增端到端评测实际运行 GPU 分类、确定性选模和 Bedrock 目标调用，保存输入、配置、输出、耗时、用量、评分及失败原因。开发参考标签、正确答案和评分标准不会发送给分类器或目标模型。

场景目录只用于评测，不是生产路由的题库。用户自由输入不会与这87道题匹配后选模；模型仍根据实际请求、附件类型和输出要求动态判断。

## 覆盖范围

第一版有 **87 个用例、25 类场景**，其中 **71 个可尝试运行，16 个为明确记录的产品能力或评测数据缺口**。这是一份可扩展目录，不代表有限用例可以穷尽所有实际输入。页面可添加目录之外的任务和验收标准；API 每批支持最多96个场景，其中最多8个自定义场景。跨批次、不同语言、行业、难度和输入规模可继续扩展。

完整的逐用例任务、参考答案和能力缺口见 [场景清单](effectiveness-scenarios.zh.md) 和 [版本化场景定义](../app/gateway_effect_cases.py)。多轮、实时语音、工具、长上下文等必须有真实接口及输入才能验证；将需求写进文本不算实现了该能力。

## 怎么评分

| 层次 | 指标与依据 | 不应作出的推断 |
|---|---|---|
| 路由与能力 | 任务类型判断正确：识别的用途与请求匹配，例如文字问候没有误分成语音生成；另记录实际选型、无候选原因和输入约束 | 类型判断正确不代表所选型号最优 |
| 执行完成 | Bedrock真实结果、结束原因、超时、限流、输出截断 | HTTP成功、非空文本、可下载文件不等于答案正确 |
| 明确答案 | 数学数值、精确字段、JSON结构、图像颜色/OCR、转写、重排首位文档 | 单个确定性样本不代表整个领域能力 |
| 开放任务 | 逐用例验收规则、具体输出证据；用户评审与助手辅助评审分别标注 | 未评审不能算通过；助手评审不是独立人工金标 |
| 代码 | 无网络、无宿主凭据的隔离容器中执行功能测试；记录用例和结果 | 语法像代码或静态阅读不等于可运行 |
| 多模态 | 内容对照；生成媒体需要听看验收，时间定位/说话人分离需要专门标注 | 图片/音视频成功返回不能自动计为语义通过 |
| 性能 | 路由与目标分别记录P50/P95；GPU服务往返含排队、传输与验证 | 顺序调用不能推断并发吞吐；服务往返不是纯CUDA时间 |
| 成本 | 实际返回token用量 × 已知参考价格，并显示价格覆盖率 | 参考价格不是Bedrock账单；未知价格不能当0 |

数值检查要求整段输出是请求的数字；分数评分器v2接受等价的最简普通分数、Unicode或LaTeX写法，旧批次保留原自动判定与复核；JSON检查拒绝重复键、额外解释和非有限值。代码/开放任务/生成媒体不会因为 `complete=true` 自动通过。目标被截断或调用失败保留为任务失败；未接通、无候选、预算用完和待评审分别计数，不把这些样本悄悄隐藏。

页面将原“工作流相容”改为“任务类型判断正确”，将原“质量通过/已评分”明确为“任务通过/已判定”：通过要求完整输出且满足验收规则。通过率 = 通过数 / 已判定数，必须同时显示评分覆盖率、待评数、能力缺口及调用失败数。完整答案不合格（`answer_failed`）、输出未完成（`output_incomplete`）和调用错误（`errors`）分别计数；截断仍属于本次任务未通过，但不归入完整答案不合格，不能据此说模型不会解题。API 原有 `workflow_fit`、`quality_pass` 等字段及历史原始评分保持兼容。另存“已证明成功数 / 全部已记录路由样本”，避免只看已评分子集产生误解。零参考费用、空模型允许列表及缺少图片附件有独立边界检查，不混入目标答案正确率。

## 成本与性能是否平衡

每个场景可对比：

1. 三种 GPU 决策模型各自分类后，网关均衡策略实际选中的配置。
2. 在**同一个实际分类和候选池**上改用低价策略。
3. 在同样条件下改用高能力策略。

对照策略不是人工指定的“标准最佳模型”，也没有遍历所有Bedrock模型。若实际路由失败而某个已测对照通过，则记录“相对于已测对照可避免的失败”。若双方都通过且实际路由参考费用更高，则记录有更便宜的已测可行替代。缺少评分或价格的样本不能参与相应结论。

本次评估三种**决策模型及其选模结果**，并非把目录中124个Bedrock型号逐一执行所有任务。报告列出实际调用到的目标模型；没有被调用的型号不会因此获得新的业务质量分数或精确评测映射。

同一场景内，目标ID、实际模型配置、工作流、完整任务、附件和输出上限相同时，只调用一次目标模型，结果供各方案共同引用。导出有 `observation_id` 和 `reused`，真实调用尝试数单独累计。共享结果有利于控制变量，但**不是重复抽样**；不能把三种路由器的共享输出当三份独立证据。三行参考费用也不能相加当成本次实际支出。

按场景顺序及提交的决策模型顺序执行，未做随机交错、冷启动隔离或多次重复；这些延迟只能描述本批次。目标延迟分位数使用带有返回耗时的结果，无法取回耗时的超时/失败另记，不伪造其耗时。

一批最多192次目标调用尝试，单次输出最多16384 tokens；界面、API和命令行的新评测默认均为16384，可调低。自定义场景未设置上限时采用本批上限，显式设置更低上限时保留该限制。实际测试报告写明使用的上限，历史批次仍保留原预算。推理模型可能将预算用于推理而未完成最终答案，这属于该预算条件下的未完成，不能直接推断模型不会解题。较大上限可能增加费用和等待时间，不要求模型必须生成满额。达到总调用上限后继续记录路由，未执行的目标明确标为未测。没有自动重试或自动切换模型。

## 历史与可复现性

- `/api/gateway/effects/cases`：完整场景及版本。
- `POST /api/gateway/effects`：启动有界评测；`providers`、`case_ids`、`custom_cases`、`baselines`、`max_target_calls`、`max_output_tokens`。
- `/api/gateway/effects`、`/{id}`：按账户隔离的任务与逐项结果。
- `POST /{id}/reviews/{row_id}`：保存有证据的评审，保留原自动评分。`method` 区分 `user_review`、`assistant_review`、`isolated_tests`。同一个观察结果的评分同步到其他共享引用。
- `POST /{id}/cancel`：停止后续工作；已经送到上游的调用可能继续执行，未记录的结果状态未知。

任务元信息与逐项结果分开写入专用DynamoDB，避免单条记录过大。使用现有登录认证与180天保留策略，附件通过账户私有媒体接口访问。版本包括场景、评分器、分类协议、目录、排名和策略。ECS中断的任务不会自动重放收费调用；已保存结果仍可读取。没有引入CloudFormation、Cognito或新的GPU实例。

重复执行示例：

```bash
python -m scripts.run_gateway_effects \
  --url https://d3eipg2g3l3an3.cloudfront.net \
  --credentials /private/path/admin-credentials.json \
  --providers decider liquid h2o \
  --baselines --max-target-calls 192 --max-output-tokens 16384 \
  --output /private/path/effects-run
```

脚本保存请求、场景快照、完整结果和汇总。断开轮询时使用 `--resume JOB_ID` 只读取既有任务，不新建模型调用。凭据不得提交到仓库。

代码功能测试在本地评测工作机的隔离容器执行，不在持有AWS凭据的API进程中运行生成代码：

```bash
python -m scripts.check_effect_code \
  --evaluation /private/path/effects-run/evaluation.json \
  --output /private/path/code-results.json \
  --image LOCAL_PYTHON_IMAGE \
  --url https://d3eipg2g3l3an3.cloudfront.net \
  --credentials /private/path/admin-credentials.json
```

容器无网络、只读文件系统、非root、无宿主凭据，限制内存128MB、CPU 0.5核、32个进程及15秒。报告记录实际镜像ID、生成代码SHA-256、测试数量及失败案例。评测脚本先以正确和故意错误的实现验证，防止“测试一直通过”。

## 后续达到正式基准的条件

这版用于发现问题和回归验证，明确标记为 `visible_development_suite_not_heldout`。正式比较需要：

- 各场景多个独立样本，覆盖短/长输入、简单/复杂、多语言、噪声、歧义和模态组合；冻结独立测试集，避免依照测评结果反复改同一题。
- 行业是可组合维度，继续覆盖电商、金融、医疗、法律、教育、科研、人力、政务、制造、物联网、旅行、游戏与无障碍；每个行业都需要自身数据和验收规则。3D/CAD、机器人控制和其他当前接口不支持的输出应登记为新能力缺口，不能归入文本通过率。
- 对开放答案采用盲评、多人交叉核验及一致性统计；自动评分器先用人工金标验证。
- 对随机输出进行多次独立重复，报告置信区间及共享观察的聚类关系，不能用一次调用排名代替稳定差异。
- 向量检索用独立语料和qrels测Recall/MRR/nDCG；语音用WER/CER、说话人DER与人工听测；视频用时序标注；生成媒体评内容符合度、质量和一致性。
- 在隔离环境单独开展并发/持续负载、冷暖启动、故障、429恢复、认证和隐私测试，明确输入输出token分布。
- 以真实账单或已核实的Bedrock计价补齐成本，并分摊GPU常驻、ECS、存储及网络成本，再计算完整的每成功任务成本。

评测不会自动训练分类器、修改标签或发布校准。先用输出证据判断问题发生在哪一层，再决定是否调整分类、策略、目标配置或产品能力。
