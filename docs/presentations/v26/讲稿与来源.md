## P2 · 把高频判断，交给更快的决策模型

本页以Jev官方速度数据说明决策模型的产品定位：它是大模型的补充，适合在有限候选中高频选动作、流程、工具或模型。复杂规划、代码和开放文本生成仍由大模型处理。
TypeSafe官方发布文给出端到端70ms–500ms，并称在System One shaped queries上，相比其所比较的frontier models可快40x–200x。这里是厂商发布数据及厂商比较，不是本项目的Jev实测，不是所有任务或所有大模型的统一倍数。原文同时说明公开速度评测通常从美国西海岸笔记本发起；输入、地区、排队和模型版本会影响延迟。没有把首页另一个193.6x工作流宣传倍数混入本页。
后续使用本项目支付、路由、图片、微调、vLLM和AgentCore数据逐项验证；不同批次、输入、调用路径和硬件不混算。

## P4 · 把输出限定为可执行选择，让模型专注于判断

新增概念说明页，不是新增实测。决策模型强调输入状态与类型化输出；有限输出空间减少文本生成开销，使高频判断更易接入软件。Strands Decider 使用基座、LoRA 与 pointer head；Jev 为专有 System One API，不能根据相似接口推断二者内部架构相同。Jev发布文描述并行采样；Strands公开实现用单次前向得到候选分数，其详细原理在后续保留的v19原页说明。choice是当前候选中的选择；noul表示对陈述的支持程度，不能未经校准视为真实业务发生概率；score是给定范围内的评分。输出格式受到约束不代表语义选择一定正确。一次请求可以含共享上下文的多个独立判断；依赖新执行结果的判断需要重新提交事实。

## P34 · 让决策 Agent 与其他 Agent 原生协作
